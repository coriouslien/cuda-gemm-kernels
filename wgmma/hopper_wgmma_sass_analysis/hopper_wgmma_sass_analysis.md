For the Hopper performance investigation, combining two command-line tools:
- cuobjdump — Examine the actual machine instructions generated by nvcc.
- ncu (Nsight Compute CLI) — Examine those instructions together with the profiling metrics,

The important difference is that cuobjdump does not contain runtime stall measurements. It can

1. Dump the existing H100 SASS

This creates a text file containing the SASS disassembly.
2. Filter the SASS instructions
For example, to find asynchronous global-to-shared-memory copies:
grep -n 'LDGSTS' wgmma_sm90.sass


To find the Hopper Tensor Core instructions:
grep -n 'HGMMA' wgmma_sm90.sass


To find the PRMT instruction you identified in Nsight Compute:
grep -n 'PRMT.*R23, RZ' wgmma_sm90.sass


You can also search for several instruction families together:
grep -nE 'LDGSTS|HGMMA|PRMT|DEPBAR|BAR' wgmma_sm90.sass


The -n option displays line numbers in the generated text file, not CUDA source line numbers.
Show surrounding instructions
This is especially useful for our investigation:
grep -n -B 15 -A 15 \
  'PRMT.*R23, RZ' wgmma_sm90.sass
It displays 15 lines before and after every matching PRMT instruction.

We can then examine the nearby LDGSTS operations and other SASS instructions.

4. Connect these instructions to your CuTe source code
NVIDIA's wgmma_sm90.cu tutorial contains the following sequence in the pipelined mainloop:
// Wait for asynchronous copies
cp_async_wait<0>();

warpgroup_fence_operand(tCrC);
warpgroup_arrive();

cute::gemm(
    mma,
    tCrA(_,_,_,k_pipe_read),
    tCrB(_,_,_,k_pipe_read),
    tCrC
);

warpgroup_commit_batch();
warpgroup_wait<0>();

warpgroup_fence_operand(tCrC);


The source establishes that copying, copy completion, WGMMA submission, and WGMMA completion are deliberately ordered. 
GitHub


The SASS confirms that the generated kernel contains corresponding copy, synchronization, and matrix instructions.

This gives us a more focused performance hypothesis:

The kernel may not be overlapping asynchronous A/B copies and WGMMA computation sufficiently to hide their latencies.

Specifically, cp_async_wait<0>() requires completion of the relevant asynchronous-copy groups before proceeding, and warpgroup_wait<0>() waits for completion of outstanding WGMMA groups before proceeding.
These completion points can limit how much useful independent work remains available.

That hypothesis agrees with your earlier low eligible-warps measurement, but determining the achievable improvement requires a controlled experiment.
